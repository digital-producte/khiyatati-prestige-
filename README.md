# خياطتي (دفتر الأم المنتجة) — الإصدار 6.2

## وظيفة التطبيق
- تمت إضافة زرين واضحين: «إضافة صورة للقماش» و«إضافة صورة للمودال»، ويعملان بنفس وظيفة إضافة الصور دون تغيير التخزين الآمن.
- الإصدار 5.8 يضغط صور الطلبية تلقائيًا قبل الحفظ لتقليل استهلاك التخزين.
- عند تعذر الحفظ في localStorage، تُحفظ نسخة طوارئ للبيانات في IndexedDB وتسترجع عند فتح الحساب، ولا تظهر رسالة نجاح كاذبة.

تطبيق ويب لإدارة ورشة الخياطة والمشاريع المنزلية. يستخدم Firebase Authentication لتسجيل الدخول وFirestore للمزامنة، مع الاحتفاظ بنسخة `localStorage` للعمل عند انقطاع الإنترنت عبر service worker.

## الملفات

- `index.html`: هيكل الواجهة، النماذج، الأقسام، النوافذ المنبثقة، وأزرار التفاعل.
- `style.css`: قواعد CSS المحلية الخاصة بالتطبيق، مثل الخط العام، تأثيرات الرأس والخلفيات المنبثقة.
- `script.js`: منطق التطبيق، إدارة البيانات، العرض، النسخ الاحتياطي، التحقق من الإدخال، ومعالجة الأخطاء.
- `firebase.js`: إعداد Firebase، تسجيل الدخول بالبريد أو Google، إنشاء مستند المستخدم ومزامنة البيانات داخل `users/{uid}`.
- `manifest.json`: إعدادات تطبيق PWA واسمه وأيقونته.
- `sw.js`: service worker للتخزين المؤقت ودعم التشغيل دون اتصال.
- `icon.png`: أيقونة التطبيق.

## موضع دمج حاسبة التسعير

تم وضع بطاقة HTML الجديدة داخل قسم الميزانية في `index.html` قبل إدارة المصاريف. تحتوي البطاقة على حاسبة فرعية للمصاريف الإضافية، وحاسبة فرعية لحق التعب بالدقائق، وحقل تكلفة السلع، وأزرار النسب السريعة، ونتائج الحساب، وزر حفظ النتيجة.

أضيف منطق الحاسبة في `script.js` ضمن قسم منطق الميزانية، ويشمل الدوال `calculatePricingBreakdown()` لحساب تفاصيل المصاريف وحق التعب، و`calculatePricing()` للتحديث اللحظي، و`setPricingProfit()` لأزرار النسب السريعة، و`savePricingCalculation()` للحفظ، و`renderPricingHistory()` لعرض النتائج المحفوظة. بالنسبة لحق التعب، إذا كان مجموع العمل 90 دقيقة وقيمة الساعة 300 دج، يحسب التطبيق: `90 ÷ 60 × 300 = 450 دج`. يتم الحفظ في المفتاح الجديد `momprenuer_pricing_calculations` دون الكتابة فوق أي مفتاح سابق.

## نتائج الاختبار

تم اختبار تحميل التطبيق، إضافة زبونة وحذفها، إضافة طلبية مع صورة قماش وصورة مودال، التبديل بين الوضعين النهاري والليلي، تصدير نسخة JSON، ورفض مصروف بقيمة سالبة. كما تم فحص صياغة `script.js` وتشغيل التطبيق محليًا بعد كل مرحلة.

## نتيجة فحص الأمان

إعداد Firebase الموجود في `firebase.js` هو إعداد Web عام؛ `apiKey` الخاص بتطبيق Firebase ليس مفتاحًا سريًا بحد ذاته. يجب ضبط قواعد Firestore في لوحة Firebase بحيث تسمح للمستخدمة بالقراءة والكتابة على `users/{uid}` عندما يساوي `request.auth.uid` قيمة `{uid}`.

### مفاتيح API أو بيانات حساسة

لم يتم العثور على مفتاح API أو رمز وصول أو كلمة مرور أو بيانات اعتماد ظاهرة مباشرة في ملفات التطبيق. توجد روابط عامة فقط إلى Google Fonts وTailwind CDN وLucide CDN.

### مواضع عرض نص المستخدم مباشرة دون تنظيف

المواضع التالية تبني `innerHTML` باستخدام قيم قادمة من بيانات المستخدم أو النسخة المستوردة دون تنظيف HTML:

- `script.js:272-317` — بطاقة VIP وقائمة الزبونات وحقول الاسم والولاية والهاتف والملاحظات والقياسات.
- `script.js:325-326` — قائمة اختيار الزبونات المسجلة.
- `script.js:555-604` — بطاقات الطلبيات النشطة وحقول الزبونة والمنتج والملاحظات والقياسات.
- `script.js:622-634` — بطاقات الأرشيف والمنتج واسم الزبونة.
- `script.js:713-724` — تفاصيل الأرشيف الشهري، بما في ذلك الطلبيات والمصاريف والفترة.
- `script.js:753-781` — قائمة المصاريف والأرشيف المالي.
- `script.js:831-848` — بطاقات الأهداف وعناوينها وقيمها.
- `script.js:878-881` — قائمة المخزون وأسماء الأقمشة والوحدات.

لم يتم تعديل هذه المواضع في خطوة فحص الأمان، التزامًا بطلب عدم تغييرها بعد رصدها.

- `privacy.html`: سياسة الخصوصية.
- `terms.html`: شروط الاستخدام.

- عزل التخزين المحلي حسب Firebase UID لكل حساب، مع الحفاظ على بيانات الحسابات المختلفة على الجهاز نفسه.
